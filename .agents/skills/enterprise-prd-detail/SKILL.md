# 企业级详细 PRD 设计 Skill（本地原创适配）
## 使用条件与边界
只负责产品设计，禁止修改真实前后端、数据库或生产接口。总控：`product-design-stage` D3；必须先读取 D0~D2 成果。不得虚构真实数据、政策或实时运价。
## 输入
`docs/design/00-intake/`、`01-discovery/requirements.csv`、`02-architecture/`；设计约束和已确认角色。缺少事实要“待核实”，不要自造。
## 输出
- `03-prd/prd-overview.md` 产品全局边界、模块图、角色权限、数据来源、约束。
- `03-prd/modules/MOD-xxx.md` 按模块的完备 PRD；不能仅一个总表。
- `03-prd/data-interface-requirements.md` 数据对象、来源、时间特性、API 需求及失败处理（只是契约，不编写接口）。
- `03-prd/traceability.csv` 需求→来源→角色→流程→模块→页面→原型→验收。
## 模块 PRD 不可省略项
1. 模块/菜单定位、适用角色、业务目的、上游数据与下游业务。
2. 业务流程：入口、正常路径、回退、分支、前后置条件。
3. 数据字段表：字段 ID、名称、类型、单位、是否必填、默认、取值域、显示/编辑、数据来源、校验逻辑、敏感级别。
4. CRUD 与按钮：出现条件、可操作角色、二次确认、重复提交策略、冲突解决。
5. 状态机：对象状态、触发事件、权限、状态转换、并发与撤销。
6. 列表/表单/弹窗/详情/下钻页：字段、分页排序筛选、空态、加载态、错误态、响应式。
7. 数据和集成：对接系统、事件、请求/响应语义、数据更新周期、超时重试和降级要求。
8. 验收项 `AC-001` 等：Given/When/Then，正常、边界、异常、权限、数据准确性。
9. 不在范围、前置依赖、假设、证据、待确认项。
## 特殊产品领域
- 物流：供需→方案求解→运力匹配→运输任务→执行追踪；按用户确认流程，不擅自调换顺序。
- 交通能源：区分订单、推演、派单、补能预测的对象和状态；预测注明输入数据时效及可信范围。
- 地图/驾驶舱：GIS 图层/缩放/交互与展示指标应追溯来源；不得将演示路线当真实轨迹。
## 质量闸门
一个需求至少有来源 ID、角色、业务流程、模块、页面、可验证 AC；字段含义不可互相矛盾；关键业务状态可闭环；不允许只提供图片替代可编辑 PRD。
## 与原始 Skills 协同
先参考 `prd-development` 的产品 PRD 框架；`user-story` 生成验收条件；大模块调用 `epic-breakdown-advisor`。当前 Skill 补齐企业系统实现前的字段/页面/规则深度，而不覆盖原始文件。

# 多式联运 / 交通能源 / GIS / 驾驶舱的专项设计约束

## 物流与能源业务
- 路线求解：区别候选路网、费用数据口径、时效区间、限制条件、运输方式/节点切换；不能展示不存在的真实列车/船舶动态。
- 多式联运：方案求解 → 方案确认 → 运力/供需匹配 → 运输任务组织 → 事件跟踪 → 交付；具体项目已经确认的顺序优先。
- 一单制：明确订单、任务、运段、批次、车辆/列车/船舶、EPCIS 事件等实体间一对多与状态同步关系。
- 交通能源：需求预测与充电排队必须区分计划进站车辆、实时设备占用、充电功率、停留时间、当前/预测队列。预测结果要带模型假设、刷新时间和置信度表达。

## GIS 地图
- 地图数据来源应注明高德 JSAPI、公开轨迹、人工维护、模拟示意的区别；收费 API 和授权能力不得假设已开通。
- 图层/图例/缩放/聚合/框选/选中/回放/跟随/时间轴的状态与交互必须说明。
- 中国、辽宁等行政区地图展示要使用可靠行政区划数据，不用缺失岛屿的自制示意图声称精确。

## 驾驶舱
- 驾驶舱独立于业务 CRUD 页面设计。指标记录名称、公式、范围、时间粒度、来源、刷新频率、空值处理和钻取目标。
- 没有真实来源的数字不能写成生产数据；演示值要显著标记“示例”。
- 全屏地图、悬浮面板、渐隐过渡、Three.js/GSAP 动画需先定义交互契约和性能目标，再做技术实现。

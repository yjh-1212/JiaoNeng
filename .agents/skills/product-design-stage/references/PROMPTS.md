# 可直接复制到 Codex 的命令提示词

## 启动设计阶段
调用 product-design-stage Skill。不要写正式业务代码。请先确认当前 `docs/design/design-state.json`，按 D0 开始梳理现有文件、业务目标、范围、数据来源。输出第一节点所需文档并总结冲突与待确认事项；未经批准不得进入 D1。

## 继续下一节点
继续 product-design-stage，只执行**第一个未批准的设计节点**；先读取此前获批成果及当前项目资料，再按模板补全。完成后执行 `check --stage Dn` 并给我可审查的成果摘要；等我确认。

## PRD 写到可以开发
基于已经确认的业务流程和菜单架构，逐模块生成 PRD。每个模块包含字段字典、角色动作、业务状态、前后置条件、边界规则、错误分支、接口数据需求与 Given/When/Then 验收条件。不得只输出摘要或效果图。检查每条需求在追踪矩阵中的去向。

## 全量页面设计
基于 PRD 生成全部本期页面清单和逐页面规格，覆盖所有菜单、下钻页、表单、弹窗、加载/空态/错误/权限不足状态。先输出页面信息架构与布局，再形成统一 UI 设计系统和页面视觉稿。业务列表页面不添加无依据统计图。

## 独立高保真原型
只能在 prototypes/design-preview/ 生成高保真交互原型；用本地标记为“示意”的数据完成全部关键路径演示，严禁请求真实生产接口。提供运行方式与页面索引，使用浏览器走查并记录结果。不得触碰 frontend、backend、src、数据库和部署配置。

## 设计验收和冻结
对照 D0-D5 已批准成果和追踪矩阵，核查需求覆盖、菜单死链接、页面操作、状态流转、原型一致性、P0/P1 问题。形成 D6 评审报告、问题关闭记录、审批凭证。不要自行登记批准；等我明确确认后再冻结。

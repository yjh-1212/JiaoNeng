# 产品开发工作流（E0-E5）
## 入口
必须存在并完整校验 `docs/design/07-baseline/design-baseline.json`；**用户明确批准开发后**才可以执行 `authorize`。无冻结基线时停止，回到第一阶段。第二阶段不会修改设计成果。
## E1 技术设计
读取 D3/D4/D5，形成技术架构、模块-AC-任务映射、数据与 API 技术合同；所有不确定项登记风险，不擅自写业务规则。
## E2 后端开发
按 `backend-development` 组织 Node.js、SQLite、参数校验、状态转换、接口及数据来源，完成数据库迁移与真实读写测试。不存在上游来源的数据必须标记模拟/不可验证。
## E3 前端开发
按照冻结页面清单、视觉规范和交互原型实现列表/搜索/表单/详情/弹窗/权限/状态反馈；从 API 获取数据，不以 mock 冒充生产数据。
## E4 联调与专项
地图 API 实现使用 `amap-jsapi-skill`；Google Maps 迁移场景才启用 `amap-map-agent-skills`，普通地图不启用；动画只用所需 gsap skill（Vue 对应 gsap-frameworks；gsap-react 仅 React）。每条业务流程实测。
## E5 浏览器验收
以 Playwright 真实浏览器逐页面走查、截图对比、正常与异常路径测试。提交测试结果、问题闭环、设计一致性差异清单。无用户确认不称为阶段验收完成。
## 禁止事项
设计冻结未验证、无用户授权、直接覆盖正式设计、伪造实时/真实数据、自动发布/部署、擅自新建不在设计里的功能。

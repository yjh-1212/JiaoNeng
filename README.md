## 运行

需要 Node.js 24 或以上版本。

```powershell
npm install
npm run build
npm start
```

打开 http://127.0.0.1:3100 。`npm run dev` 支持前端修改后自动构建；后端修改后需重启服务。

## 数据与操作

公开车型资料和项目业务数据分开保存。350/513kWh 车型档及特定场景能耗引用公开厂家资料；实际车队型号、SOC、路线、车辆身份、站点能力、订单、磅单、电价和费用均为业务仿真或人工仿真登记，页面保留“仿真”及来源入口。

初始数据包括 2 个主体、12 位司机、18 辆车、3 个场站、9 个工位、8 个需求、24 个订单、16 个运输任务、27 个车次、4 个补能计划、12 条补能作业、12 条费用、432 个历史定位采样，以及站级/工位负荷和电网/绿电/储能仿真边界。数量随正常业务操作变化。数据有外键关联，不是各页面独立的展示数组。

可验证主流程：需求/订单确认 → 交能推演与DeepSeek分析 → 人工确认方案 → 核对车辆/司机并手动生成待派发任务 → 整批校验并派单 → 司机接单、反馈车次装运卸货 → 提交完工 → 管理员核验或退回 → 已核验交付汇总。需求来源仅在最后生成时创建对应订单并占用数量；单纯推演不占用。报告量不计作核验量，费用更正版在核验后替代旧版，补能作业更正与费用更正分别处理。

推演、排队预测、负荷预测、站点容量和车辆电池投放均为可追溯的条件模型，保留输入和版本。没有实际合同、BMS、道路许可、接电、用地或现场设备协议时，不将参考模型结论认定为现场运行依据。能源策略不发送设备控制命令，规划推荐不创建实际投运资产。

推演逐车次计算装卸、重空载运输、驶入场站、等待和补能节点，并检查SOC、适配、时间窗口、库存与工位共享功率。能源工作区比较原时序、绿电与储能方案；规划工作区支持多候选和建设阶段比选。经营分析按有效核验记录统计并下钻来源，缺少费用类别时不展示完整单位成本。资产支持租赁、维保、电池去向与可用核验；个人信息支持本人资料及密码更新。

助手可查询资料、解释预测/规划/风险、整理运输输入卡；条件转入新版推演工作台核对与计算。不会把聊天内容直接变成已派发任务。

## 外部服务

服务端优先读取环境变量，其次读取本机 `api_key` 中的高德/DeepSeek 文本配置。密钥目录和 `.env` 不进入源码。环境变量名称见 `.env.example`。

高德 JSAPI 的浏览器 Key 用于加载地图，安全密钥由服务端代理附加。DeepSeek Key 仅在服务端读取。智能助手会将当前账号授权范围内的少量业务摘要发送给 DeepSeek，由用户在页面发起查询；不提供模型直接执行派单、费用核验、授权或设备控制的工具。

常规Node验收使用空的外部服务配置或确定性模型替身。新版推演浏览器验收使用隔离仿真库、真实高德路网和明确的模型替身；设置 `SCENARIO_LIVE_AI=1` 后使用真实DeepSeek，仅发送仿真参数、方案指标及瓶颈汇总。密钥、坐标、联系人和车牌不发给推演模型；模型失败保留计算结果并提供重试。当前这批仿真测试数据已有用户授权。`tests/live-browser.mjs` 是原智能助手的独立真实AI测试，常规测试不运行。

# D6 产品设计综合评审报告

版本：V0.2-D6-RC1；日期：2026-10-13；评审执行：设计代理；批准人：当前用户。状态：已完成评审和CR-001修订自检，等待本轮复审；未冻结、未进入开发。

## 产品目标、流程和完整性

建设对象是从零设计的交能融合智能体平台，实际运营和项目汇报并重。九模块全部保留，需求→订单→交能推演→全批派单→司机多车次执行→管理员核验→经营复盘形成设计闭环；场站、能源、规划和安全共享业务对象与数据口径。

两类角色不变：管理员按主体范围和操作授权，司机仅本人任务与必要补能信息。整批派单全成才生效，通知投递和司机接收独立，司机报告不直接计入核验完成。规划、资源投放、置换、预计费用和实际投运/计量分别表达。

本轮逐模块审查及依赖见[module-review.md](module-review.md)。没有借鉴辽粮的粮食交易、供应商竞价或无依据综合评分，保留用户指定的顶部导航及上下布局。

## PRD深度、页面覆盖与一致性

57项需求、47项功能、47份逻辑接口契约、261字段和171条验收设计均可追踪；26目的地有页面规格与有效原型路径。设计映射统计与真实交互测试严格区分，详见[覆盖报告](coverage-report.md)及[逐项矩阵](requirement-audit.csv)。

240个不同字段具备319处逐页放置；另外21项COM共用字段有共用契约和控件定义，处理边界见common-field-review.csv，不能将它们全部称为已独立上屏。原型证明业务流程可审阅，不能证明正式接口已经实现。

最终视觉以D5修订002为准：顶部一级导航及下拉二级菜单，下方业务内容；交能推演上条件、下地图/时序与方案；标题无说明副文案。D4侧导航等历史表述的优先关系见[设计合并规则](design-resolution.md)。这些补充随D6提交确认，不静默改写旧审批文件。

## 可用性、权限、异常专项

原型采用真实React/LobeHub/antd运行时，单HTML可以打开。管理端全页面及司机H5可运行；主要模拟流程含整批冲突、司机节点必填、完工退回、核验汇总、费用更正版、质量纠正和预警闭环。

D6额外验证键盘菜单、详情面板Tab/Shift+Tab/Escape与焦点返回、表单必填与输入保留、错误关联、无可行/计算失败区分、SOC越界、缺边界阻止推演、离线拒写、深链接返回和图表数据表。320px仍能使用折叠菜单和条件折叠；多列表格局部横滚。

测试为Windows本地Chromium/Playwright；没有实际读屏器语音、Firefox/Safari或真实H5设备测试，因此不作WCAG符合性认证或全浏览器无障碍结论。业务权限属于模拟验证，不证明服务端鉴权安全。

- D6-001：来源图标可打开但漏掉传入的专属依据。CR-001获用户同意后已在按需面板中补回，保持页面简洁。
- D6-002：表单错误文字未关联对应输入。已加入aria-invalid与稳定错误ID关联；编辑时清除旧错误。
- D6-003：历史D4导航规格与用户后续决定不一致。以本轮设计合并规则明确顶部导航优先，待候选确认。
- D6-004：真实运行参数和量化验收不能凭示例补齐。按用户要求完成公开研究，形成11条来源、20组参数候选和启用门槛；待本轮确认，仍是冻结前P1决策项。

闭环记录见[issue-closure.csv](issue-closure.csv)。D6-001/002专项复测通过；授权修改D5不等于修订稿已复审，旧D5哈希仍保留可核对。

## 数据依据、候选数值及剩余边界

[公开依据与参考参数方案](public-reference-parameters.md)补入特定车型的电池、能耗、充换电参考，也明确哪些数值由设计提出。甘肃2026市场价格信息意味着成本和策略需采用版本化分时曲线，不能把历史固定峰谷表直接套给本项目用户。

公共值不替代真实SOC、车型BMS安全规则、当月合同价格、场站功率/库存/适配、用地接电证明和数据权限。预测精度、性能、连续性已有可评审的候选工作负载与目标，但没有真实测试结果。20组候选全部禁止生产自动启用。

高德外部SDK在此前原型测试中加载失败，原因未定；本轮查阅接口资料没有等价验证账户权限或真实路径。DeepSeek只核对公开接口文档，没有读取用户Key或调用服务。不存在由公开资料推导出的现场实绩、工程批准或运营收益承诺。

# CR-001 D6审查修订提案

日期：2026-10-13。状态：用户2026-10-13明确同意“同意修订并重新自检”；已授权执行修订，修订稿仍待复审。

## 原因与可复现问题

1. PAGE-005完成推演后，点选中方案的“来源与口径”图标，面板只有共用说明，没有方案A“错开到站，等待较少；费用为已知项目”等专属依据。共用Source组件收到text但未在详情中渲染。
2. PAGE-004新建订单清空订单名称后提交，错误文字可见、焦点和输入可恢复，但输入没有aria-invalid和关联错误文本，辅助技术难以确定错误归属。

证据：docs/design/06-review/evidence/browser-review.json的R05/R10及对应截图。

## 拟进行的最小修订

- 在Source详情中加入“当前依据”内容，使用组件已有text值；说明仍在按需打开的面板中，不恢复常驻副文案。
- 表单校验失败时设置aria-invalid，并为错误文本添加稳定ID，通过aria-describedby关联；修正后清除错误状态。不改变字段、权限或业务规则。
- 顶部导航、上下布局、精简菜单、角色和正常页面视觉保持用户已确认的修订002。
- 仅修改prototypes/design-preview/source/common.jsx、source/app.jsx及必要隔离原型构建结果；更新设计测试与记录。正式源码、API、数据库和部署配置不在变更范围。

## 验收与审批影响

- R05可读取所选方案的专属依据；R10可取得错误状态及错误文本关联。
- 原71项检查及D6专项检查复核，主流程和页面无回退。
- 修订会改变D5已批准文件哈希。用户同意执行本CR后，只表示授权修订；修订成果仍需重新确认D5，之后才能批准D6或冻结。
- 不以本CR授权正式开发。

## 冻结范围决策提案（单独确认）

产品需求仍保留全部九模块、57项需求。建议先冻结业务流程、PRD和页面交互设计，真实运行参数、模型精度、性能/恢复指标和外部接入作为相应能力启用前的强制补齐门槛；不把演示数值变成生产默认或验收承诺。

这属于对D3“D6前补齐或明确范围取舍”的决策提案，用户未同意直接按未知参数冻结，而是要求“你自己从网上找一些较为真实的数据补上这块内容”。据此追加公开依据与参考参数研究；未获确认的冻结范围不视为问题关闭。若用户选择先补齐业务依据，则D6保持未冻结并继续收集资料。后续资料改变已冻结业务规则或页面时，另走CR。

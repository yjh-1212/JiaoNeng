# CR-014 求解条件统一输入

2026-10-16。用户明确要求去掉截图中的来源/主体选择与状态操作栏，“就跟辽粮的求解一样，一方面是订单带过来的条件，另一方面是手动输入的”，直接授权本地实现。

参考辽粮apps/web/src/views/Planning.vue：同一套求解表单直接展示业务条件，业务单据通过入口传入上下文，单独进入可手工填写。交能推演移除主页面来源类型、来源对象、业务主体下拉框、待测算状态及新建推演/保存条件整排栏，不增加替代模式页签。订单页“交能推演”进入时自动带入该订单，条件区默认展开；底部仅显示来源编号。主导航进入默认为手动试算，在同一套表单填写运量、货物、起终点、时间和目标。

订单/需求上下文通过hash参数保留，刷新可恢复同来源；原需求和助手传入入口兼容，不提供主页面来源切换器。手动业务主体取当前授权范围默认值；多主体账号如需调整，可在专业测算条件抽屉中选择，主体权限校验不变。手工填写保留安全默认参数，货物/运量/起终点待填写。求解动作内部仍先保存再计算，移除独立保存按钮；已保存场景与任务保留。

测算条件、重置和生成运输方案在业务条件操作区；重置恢复新的手动填写条件并解除来源关联，不删除原单据、场景或任务，未保存输入需确认放弃。带入条件可调整用于推演，生成任务仍按原规则校验实际执行来源匹配，不能静默改写订单。修改输入使旧结果待重算，DeepSeek、地图推荐及人工最终生成边界不变。

验收：主页面无截图整排；直接进入手动填写；订单入口正确带入且刷新保留订单；切回主导航或重置可手动填写；多主体设置仍受范围约束；来源失败可重试/转手动；输入默认展开；求解、聊天、重算及最终人工生成链在独立库验证，现有业务库不写入测试数据；390–1600px无横向溢出。

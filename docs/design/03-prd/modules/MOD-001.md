# MOD-001 运输订单与交能协同调度

版本：D3 V0.1 ｜ 状态：待用户批准 ｜ 依据：已批准D1需求与D2精简菜单/流程

## 1 目标、范围和定位

将需求拆分为可履约订单，在硬约束内比较运输及补能方案，并将已确认方案整批转为有效派单。

本模块覆盖5项业务功能。细分记录、详情和测算步骤位于以下工作区，不增加导航菜单：

- PAGE-004 运输订单，`/transport/orders`；prototypes/design-preview/index.html#page-004（D5规划，尚未生成）。
- PAGE-005 交能推演，`/transport/simulation`；prototypes/design-preview/index.html#page-005（D5规划，尚未生成）。
- PAGE-007 运输任务，`/transport/tasks`；prototypes/design-preview/index.html#page-007（D5规划，尚未生成）。

角色：管理员。流程：FLOW-002、FLOW-003。主体范围和操作双重校验，相关业务的引用不扩大权限。

## 3 逐功能业务规格

### REQ-001 运输需求登记

来源：SRC-004 §3.1，P0072；功能编号FUNC-001，接口IF-001；PAGE-004 运输订单内部承接。

**业务目的与场景。** 登记完整运输需求并生成关联订单，修改后能查到变更与关联记录。用户故事：作为获相应授权的管理员，希望完成“运输需求登记”，使该结果可用于关联业务且来源可复核。

**前置与输入。** ROLE-001授权主体及对应操作；对象存在或允许创建草稿，引用版本和来源有效。输入字段：M001-F001、M001-F003、M001-F004、M001-F005、M001-F006、M001-F007、M001-F008、M001-F009、M001-F010、M001-F011、COM-F022。正式动作按字段条件验证，缺少关键数据时不宣称已完成真实计算或执行。

**操作和正常路径。** 保存草稿、核对确认、拆分订单。拆单在同需求有效版本中核对已分配量，草稿保存与可拆单确认分开；部分拆分保留剩余量。

**按钮、状态和副作用。** 允许动作仅为上述清单；权限为`demand.read`、`demand.write`。写入按D2相应对象允许状态迁移，不能直接编辑state绕过动作。

取消、终止、改派、费用更正、授权变更和批量派单显示对象范围及影响并明确确认；普通查询和节点反馈不重复堆叠确认。新增/修改不默认为可删除，已有引用与实际记录通过取消/作废/新版本处理。重复提交和版本冲突遵循BR-001/005。

**分支和异常。** 并发拆单或重复提交不能超分配；需求有订单引用时取消不删除关联。 接口返回字段缺项、权限、版本、资源、数据时效或计算错误的具体语义，保留用户输入和可重试依据。批量派单只按整批结果重试；其他批量接入按事件来源唯一键逐条核验，不借此改变派单原子性。

**页面内呈现。** 订单工作区内需求区和登记/拆单抽屉；查看需求来源及拆分结果。 表单使用上述输入中可编辑字段；结果展示运输需求标识、业务状态、当前版本、业务结果或批量内容。列表按所属对象编号、主体、状态和适用时间范围查询，按公布字段稳定排序分页；返回保留筛选和当前位置。加载、无记录、未接入/过期、无权限、冲突、计算失败及不可行分别表达。桌面是所属工作区，司机端按H5任务上下文，D4再细化布局控件和响应式。

**输出与交接。** 输出字段：M001-F001、COM-F006、COM-F004、COM-F022；返回共用对象版本、来源/时间、结果完整性和适用审计引用。关联FLOW-002，跨页带对象与版本，不传未经核验聊天文本当执行数据。

**集成与审计。** IF-001为COMMAND语义；请求/响应字段及失败边界见interface-catalog.csv和data-interface-requirements.md。更新以业务动作/来源事件/显式计算触发，真实来源频率由协议和P-010确认；变更审计保留操作者/来源、前后版本、原因及结果，不写敏感凭证全文。

**验收。**

- AC-001：Given ROLE-001授权主体及对应操作且所需输入完整、状态允许；When 执行保存草稿及其必要后续；Then 登记完整运输需求并生成关联订单，修改后能查到变更与关联记录。
- AC-001-B：Given 并发拆单或重复提交不能超分配；需求有订单引用时取消不删除关联。对应边界或缺失条件；When 尝试该动作；Then 明确缺项或拒绝原因，不产生未经核验的生效状态、重复计量或伪精确结果。
- AC-001-P：Given 用户无对象范围、无动作授权；When 从页面、深定位或接口请求该能力；Then 拒绝且不返回越权正文、不改变对象状态。

**待核实与排除。** QC-01;QD-01；参数和来源资料见parameter-register.csv。本功能不因为原型可点击就视为模型、设备接入、量化精度或实际经营效果已验收。

### REQ-002 订单管理

来源：SRC-004 §3.2，P0079；功能编号FUNC-002，接口IF-002；PAGE-004 运输订单内部承接。

**业务目的与场景。** 新增编辑复制查询取消订单可追溯；变更运量或时间时识别关联方案和任务的影响。用户故事：作为获相应授权的管理员，希望完成“订单管理”，使该结果可用于关联业务且来源可复核。

**操作和正常路径。** 新增、编辑、复制、查询、取消订单。订单绑定单一来源需求；复制生成无执行和费用的新草稿，确认时再占用可分配量；关键变更使关联待派方案需重算。

**按钮、状态和副作用。** 允许动作仅为上述清单；权限为`order.read`、`order.write`、`order.cancel`。写入按D2相应对象允许状态迁移，不能直接编辑state绕过动作。

# 交能融合智能体平台详细PRD总册

版本：D3 V0.1 ｜ 日期：2026-10-13 ｜ 状态：待用户批准

## 1 建设目标和边界

面向庆阳新能源重卡运输，以订单组织、交能推演、运输执行、补能能源协同和经营复盘形成闭环，并用真实运营数据辅助场站与资源投放。实际运营与项目汇报并重，源数据、口径和权限一致。

D0—D2已获用户批准，当前沿用精简菜单：运营总览直接入口、18个二级菜单、司机H5“任务/补能/我的”。九个业务模块、47项功能、9项非功能要求及1项运营汇报约束全部保留。模块PRD描述业务能力，页面通过所属工作区承载，不恢复详情、记录等菜单。

本轮只编写设计文档。D4编写26个工作区/通用目的地的页面规格，D5制作独立HTML原型，D6审查覆盖和冻结条件；当前不修改正式源码、接口、数据库或部署配置。

## 3 模块总览和协作关系

| 模块 | 目的 | 上游 → 下游 |
|---|---|---|
| MOD-001 运输订单与交能协同调度 | 需求拆单、求解比较、确认派单 | 基础/运力/场站/能源 → 任务/补能计划 |
| MOD-002 运输组织与执行管理 | 一车一司机、多车次执行及完工核验 | 确认方案 → 实际车次/事件/结果 |
| MOD-003 充换电运营管理 | 场站作业、补能计划、排队预测和优化 | 任务/设备/能源 → 实际补能/用能需求 |
| MOD-004 交通能源协同管理 | 负荷预测、策略和协同计划 | 补能需求/能源边界 → 可复核协同安排 |
| MOD-005 场站智能布局与资源规划 | 候选点、容量和车辆电池投放 | 实际流量/资源/可研条件 → 规划建议 |
| MOD-006 运行监测与安全保障 | 监测、异常处置、同口径总览 | 数据与反馈 → 影响识别/处置/汇报 |
| MOD-007 成本管控与综合运营管理 | 费用资产合作及经营复盘 | 车次补能/证明/规则 → 核验费用与报表 |

## 4 角色和操作授权

ROLE-001为管理员，所有读取与修改同时满足业务对象范围和对应操作授权；不得因可看任务就读取未授权成本、其他主体完整档案或能源数据。ROLE-002为司机，仅本人当前或获准历史任务及必要补能、异常资料可见。

沿用D2 permissions.csv的操作代码。SYSTEM只是接入、计算、聚合事件执行者，不是第三类登录角色，不代替管理员确认。原始来源事件不能自行更改归属、授权或业务配置。

## 5 跨模块不变量

1. 主体、需求、订单、任务、车辆、司机、车次、场站、设备、电池等共用唯一标识。运力与资产编辑职责分开，不重建同一车辆。
2. 需求分配量、订单计划量、任务计划量、实际车次交付量分别计量。取消量不算履约；任务数不等于车次数；同一车次不能在多个任务重复计量。
3. 已确认方案引用订单、资源、参数和输入快照版本。影响可行性的变更使待派发方案失效；已执行事实保留，采用新版本或余量替代任务协调。
4. 派单整批生效：先统一核验版本、权限、资源时间冲突、补能及能源边界；任何一项失败，整批无新增有效指派和派发状态。失败展示逐项原因，修正后重试；同一请求重复提交不得重复派发。
5. 原计划不代表真实预约、设备占用、交付、计费或电力控制。实际作业可无计划关联，但必须有可核验来源和对象，不伪造计划。
6. 司机节点或完成提交不是管理员核验。遥测与人工事件冲突进入核验，不按最后到达时间简单覆盖事实。
7. 费用、参数、方案和归属变更保留版本。更正金额与原记录关联，不能重复计入原费用与替代费用。
8. 所有展示区分真实采集、人工登记、算法推算、演示模拟；未接入、延迟、无记录、无权限不当作零。

详见business-rules.md；状态以已批准D2 state-permission.csv为依据，D3补充动作条件，不静默增加终态或操作角色。

## 6 数值、时间和统计口径

业务时间显示Asia/Shanghai；传输包含时区或偏移，保存同时保留来源时间与接收时间，跨日统计用统一半开区间。吨、km、kWh、kW、分钟和人民币元作为默认显示单位，源单位与精度保留；不按界面显示小数截断计算输入。

数量及实际费用以已核验有效记录计量；预测与实际对比必须同对象、同区间、同单位及同模型口径。指标定义见metrics.md，缺项与样本范围必须可见，不能补出完整利润或唯一最优分数。

## 7 数据和外部依赖

需规八类数据完整保留：运输业务、车辆运力、交通路网、场站设备、补能业务、能源资源、价格成本、规划资产。还需账号授权、参数和审计记录支持。

目前未取得试点订单样本、设备协议、实际计量、电价和接电资料、车型兼容、独立可研或量化验收规模。外部来源状态按“待核实”登记，设计不承诺已接入。接口契约只定义业务请求/响应/失败语义，不编写API或数据库。

## 8 非功能要求和验收层次

九项非功能要求保留REQ-048—056。PRD以正常、边界、错误、权限、追溯及数据真实性验收描述承接；常用查询、刷新、推演、预测、恢复和并发数值由parameter-register.csv列出责任方及截止节点，不凭空承诺秒数或精度。

D3自检验证文档覆盖与一致性；D5只验证标注样例的交互；开发验收必须另有真实前端/API/数据及授权，不能由HTML原型替代。D6冻结前须补齐关键规则和量化指标，或明确排除受影响的实际运行能力。

## 9 范围排除和风险

保持上游排除：实体工程、完整金融财税和支付充值结算、独立车队/站长等角色、设备自主控制、交易市场、语音输入和定时推送不默认纳入。车辆、电池和站点资源投放为建议测算，不是资产采购或拨款审批。

外部接口、成本公式、SOC余量、排队模型、能耗修正、事件核验和SLA尚待资料确认。所有未决项有影响范围、责任类型、不可用时表现及冻结前决策门槛，不用虚构默认值掩盖。

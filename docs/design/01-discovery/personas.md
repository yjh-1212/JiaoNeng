# D1 角色与典型场景

版本：V0.1 ｜ 日期：2026-10-13 ｜ 状态：待批准

本文件描述项目资料定义的角色和任务，不虚构人物姓名、年龄、画像占比或访谈结果。

## ROLE-001 平台管理员

- 身份：平台运营及业务管理人员；依据需规§2.2、§11.4。
- 目标：完成运输需求组织、运输补能协同、运行处置和经营分析，形成可信的管理汇报。
- 触发：收到运输需求；需派发或调整任务；车辆/场站/能源异常；业务复盘或规划比选。日常频次与工作量待真实试点确认。
- 操作：维护需求订单和资源，核验输入，推演比较确认，生成并派发任务，监测司机及场站反馈，处理异常，确认完工，分析成本和规划方案，维护授权配置。
- 数据：订单、车辆司机可用时段、GPS与SOC、路网、设备及电池适配、供电负荷和价格、实际执行、成本及资产资料。
- 关注：是否按时完成、车辆电量是否安全、场站能否服务、等待和费用来自哪里、异常影响哪些任务、汇报指标能否下钻。
- 权限边界：仅使用获授权的数据和操作；不能把AI建议直接当成已确认派单；设备自动控制、未授权资金交易不在默认能力内。管理员内部授权如何细分待D2/D3确认。
- 异常：无可用车辆、输入缺失、任务冲突、无可行方案、司机拒单、场站故障、断流、负荷超限及成本缺项应有对应处理入口。
- 典型成功结果：一张订单产生可追溯方案、计划和执行任务；变更影响被识别，司机与管理端结果一致；完工后能解释计划实际差异。

### 管理员旅程

1. 业务准备：核对主体、装卸点、车辆司机、场站能源资料；缺项可见。
2. 需求组织：登记需求形成订单；来源与后续记录可追溯。
3. 推演比选：先满足硬约束，再比较成本等待；明确输入和方案版本。
4. 确认派发：确认方案、资源与补能安排；发现冲突时修订或重算。
5. 执行协调：查看司机承接、装卸及补能事件，处理影响运输的风险。
6. 结果归档：核对完成量和记录，确认完工；复盘成本和时序偏差。
7. 管理决策：统一统计窗口生成总览，比较资源规划，保留测算假设。

## ROLE-002 司机

- 身份：被指派新能源重卡运输任务的驾驶人员；依据需规§4.3—4.5、§11.4。
- 使用端：用户2026-10-13确认采用手机H5；不默认为微信小程序或原生App。
- 目标：快速明确要运什么、去哪里、何时完成、在哪里补能，及时反馈进展和异常。
- 触发：收到任务、开始执行、到达装卸/补能节点、发现无法执行或故障、提交完工。通知技术和频次待定。
- 操作：查看关联任务，确认/拒绝并反馈原因；查看路线和补能安排；上报开始、装卸、途中及完成信息；提交异常和完成资料。
- 必要数据：任务编号、装卸位置、计划时间、运输要求、车辆关联、推荐路径、补能站与时间安排、管理员处置结果。
- 权限边界：仅查看自身关联业务；不能查看全平台成本和其他司机任务，不能修改能源参数、调度规则或自行确认全局改派；AI问答入口暂不默认开放给司机。
- 异常与离线：反馈提交失败需明确结果，保留可重试信息是设计建议；离线事件缓存与恢复策略待确认，不虚构H5已有后台通知或离线定位能力。
- 典型成功结果：司机接受任务并反馈节点，管理员能看到对应实际时间；故障/拒单进入管理员处置链；完成提交与管理员完工确认有区分。

### 司机旅程

1. 任务进入：登录H5，仅看到自身待接和执行任务。
2. 核对承接：查看位置、时间、运输与补能安排，接收或说明不能执行原因。
3. 执行反馈：按实际作业反馈节点；定位、遥测与人工反馈分别标明来源。
4. 补能与变化：查看当前有效补能计划；收到改派或计划变更时能识别版本与影响。
5. 异常反馈：上报原因及必要信息，查看管理端处置进展。
6. 完成提交：提交实际完成信息及适用凭证，等待管理员核对；补充资料或重试不会混淆完成状态。

## 业务参与方与账号的区别

运输企业、个体户、车队、矿区厂区、场站、能源方、电池银行及政府汇报受众可以出现在档案、合作、数据来源或汇报中。当前不单独新增操作角色。需独立登录时登记变更并明确业务任务、可见数据与端形态。

## 后续核验对象

| 核验对象 | 需回答的问题 | 当前证据 |
|---|---|---|
| 调度业务负责人 | 一单多趟如何组织、订单任务车次关系、优先目标、改派与完工标准 | 文件和用户目标次序，尚无一线访谈 |
| 司机代表 | 接单拒单与节点反馈是否符合实际作业、手机网络、凭证需求 | 文件场景及H5确认 |
| 场站及能源数据负责人 | 设备、电池、负荷及计费数据可取得哪些、时效如何 | 需规类别，无接入协议 |
| 成本与经营负责人 | 电费、服务费、租赁维保与司机费用的实际口径 | 需规范围，无真实费用样本 |
| 建设方/产品负责人 | 首版实际验收规模、管理员数据授权、原型演示范围 | D0批准，全量设计指令 |

上述对象是需要获取知识和批准的参与方，不等于新增平台账号。

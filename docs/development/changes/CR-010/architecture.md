# CR-009/010 本地实现交接

依据：冻结的CR-009目标式推演与CR-010浮层/人物对话增量，分别保存用户明确开发授权。原冻结PRD、原型及父基线未覆盖；产品当前版本由active-revisions.md导航。各节点由开发代理依用户既有推荐方案委托自检，并非用户逐项签署。

## 页面

`client/goal-simulation.jsx`接管原推演菜单，上方业务条件、右侧测算条件抽屉，下方真实高德路网与执行明细。`scenario-panels.jsx`复用选点、专业配置和明细。`floating-plans.jsx`在地图内右侧展示430px推荐面板，中屏380px；内部滚动，可收起。地图适配、控件与回放给面板留出空间，800px以下面板进入地图后方文档流。采用按钮为人物入口留出空间。

`scenario-chat.jsx`提供右下人物按钮及右侧440px非模态聊天窗，关闭保留消息、来源切换隔离，Escape关闭并恢复焦点。生成前咨询输入与目标，生成后解释候选、比较与提出调整。模型输出经程序验证后显示原值→新值卡片，点击才重算；过期版本、未保存条件、已生成任务禁止应用。迟到的跨来源响应不进入新会话，失败保留问题/方案并可重试。

人物为内置imagegen生成的透明PNG，原文件完整复制到`client/assets/jiaoneng-ai-v1.png`。构建采用esbuild文件资源输出，页面不依赖临时文件或外部图片地址，生成说明见avatar-generation.md。

## API与模型

| 接口 | 行为 |
| --- | --- |
| POST /api/scenarios/fleet | 主体范围内按状态、司机、排班、占用、载重/容量/SOC与补能兼容筛选可用运力 |
| POST /api/scenarios/:id/adjust | CR-009保留的有界调整预览接口 |
| POST /api/scenarios/chat | CR-010生成前引导；有结果时按场景版本与所选候选解释/解析调整；不写业务对象 |
| scenario.save/run | 保存并计算直接填写、需求或订单来源，输入/资源版本复核 |
| scenario.confirm | 仅确认方案 |
| scenario.dispatch | 最终人工操作，原子绑定或新建需求/订单及待派发任务 |

`scenario-adjustments.mjs`调用真实DeepSeek官方接口，JSON模式、关闭thinking、30秒超时。问题上限500字、历史最多10条且每条2400字。服务端重新读取授权场景事实，历史不作为系统规则；发送数字条件、指标、瓶颈与限制，不发送密钥、联系人、车牌、坐标或整库。未知字段、越界值、无时区日期拒绝；模型不可调用业务命令。已生成场景仅解释，返回空patch。

既有登录、主体范围、操作授权与CSRF在新接口继续生效。调用外部服务后复核场景版本，冲突409；仅preview不保存输入。AI输出失败显式返回错误，程序计算结果仍保留。

## 计算与执行

`scenario-goals.mjs`枚举1–60辆范围内全部车数、每车数3种启发式策略；固定车数测完成时间、按期限求最少可行车数、按期比较较低成本。重复方案合并为最多3个，不保证一定3个，不宣称全局最优。司机工时、SOC、装卸/补能工位、时间窗口等为硬约束；无解显示模拟交付缺口。

`scenario-engine.mjs`逐车次计算有限资源排队、装卸、真实有向道路时长/能耗和补能。补能规划需确保后续充电站可达；最后一趟只要求安全交付，避免无必要空驶使方案误判。无需补能时允许空场站。

实际运力按车队版本约束；候选保存自己的车数/期限覆盖值，最终映射据此校验。直接试算不创建需求或订单；最终人工明确选择关联匹配来源或新建业务对象，检查运量、起终点、货物、版本、实际车/司机和站点，一次事务成功或整体回滚。新生成无补能任务可通过原批量派单校验，旧任务路径仍兼容。

## 证据与限制

测试使用独立内存SQLite，不向用户当前业务库写测试任务。公开道路为高德通用驾车路网，车辆、现场能力、社会车流和费用为参考/模拟；不冒充实时运营数据或货车通行许可。业务数据真实性和现场启用要求仍沿用原交接。没有部署发布。

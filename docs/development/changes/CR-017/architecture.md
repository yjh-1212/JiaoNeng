# CR-017 运输任务工作区实施记录

## E0 依据与范围

按用户“可以按这个来帮我修改完善”实施已批准设计图及 CR-017 增量规格。授权见 authorization.json，冻结增量见 docs/design/07-baseline/design-baseline-CR-017.json。沿用父基线和 CR-002 至 CR-016，未修改冻结文档或已批准图。

## E1 技术与任务

React/LobeHub/antd 实现 task-workbench.jsx、task-drawers.jsx、task-workbench.css，替换旧 Tasks 工作区；路由 #tasks、顶部菜单与权限模型保持不变。分为列表查询、状态待办、专用抽屉、派发预检与提交、排程、回归验收六项，均完成。

## E2 后端与数据库

新增 server/task-workspace.mjs，无数据库迁移。

| 接口 | 作用与边界 |
| --- | --- |
| GET /api/task-workspace | 按授权主体执行数据库查询、关联关键词、固定状态、日期区间重叠、分页及全量状态计数；默认10条，最大100条 |
| GET /api/task-workspace/:id | 返回实际任务关联的订单、车辆司机、车次凭证、补能、异常、事件及单条/批量操作审计 |
| POST /api/task-dispatch-preview | 只读预检；先验证整批读取范围，再提供逐任务错误和跨任务冲突，不产生派单 |

管理员读取需授权主体和操作权限；司机不能调用该管理接口。SQL 使用参数绑定；跨主体预检不泄露任务细节。最终执行仍调用既有 dispatch.batch，再次验证版本、资源与数量并整批事务提交。增加重复任务和不合法条目校验。无新增直接写库捷径。

## E3 页面

上方查询与按钮同排，下方状态标签与列表/排程切换；默认10条。列表显示任务/订单、路线货物、车牌司机姓名、时间、上报与核验量、状态待办及操作。无重复大标题和大指标卡。待派发才可选择，查询/分页/视图变化清除选择；相同条件再次查询仍重新读取。

详情分概况、车次执行、补能安排、操作记录。调整、取消、通知、异常和来源集中在右侧；核验抽屉保留逐车次依据，只读报告总量，支持通过或退回。409保留填写内容，读取最新版本后人工再确认。全局确认层高于抽屉。

## E4 业务联调

派发先预检，再人工确认；提交前资源变化导致整批失败，抽屉保留并重校验。网络中断时保留同一幂等键，核查原命令结果，避免重复派发。

调整时间后继续由既有命令标记需重算。仅未执行且无报告量的任务可明确取消并重新推演：先成功取消，再携订单进入新场景，旧任务保留；不自动生成或派发替代任务。新场景使用 URL new=1 跳过旧锁定结果，首次成功计算后清除标记。权限及最终生成确认沿用现有规则。

排程展示当前页任务的统一时间比例、车辆分组、重叠标识，明确当前页范围；不能用于认定全车队空闲，不支持拖拽直接改计划。结束任务不再提示需重新测算或通知失败，关联未处理异常仍可追踪。

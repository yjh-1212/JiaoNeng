# CR-023 PC智能体中心实现

用户范围：仅PC首批六智能体，右下方现有交能AI人物为统一入口，参考辽粮的中心页面。授权和冻结差异见authorization.json与CR-023设计清单。本轮不增加司机功能和业务主菜单。

E0：校验原冻结链及开发授权，新增CR-023清单；最终23级清单、323份冻结成果校验有效。保留原阶段批准记录，未把代理自检记成用户签字。

E1：复用React/LobeHub/antd、Express及SQLite。shared/agents.js定义六种能力、域资源和业务路由。client/agent-launcher.jsx提供全局单入口与当前业务条件；client/agent-center.jsx/css提供辽粮式完整工作区。中心以覆盖层打开，保留业务组件与未保存条件；支持刷新后的独立内部路由。原业务页面的重复AI浮窗与顶栏按钮取消。

E2：schema.sql只新增agent_conversations和agent_turns及索引、外键、JSON约束、轮次请求唯一键。会话绑定当前账号和单主体；API沿用认证/CSRF，要求管理员、ai.use和read。查询、历史、关联对象与交接重新鉴权；归档恢复和重命名验证版本。模型服务读取所选主体全量统计、有限样本和明确选定对象的业务明细，记录资源/版本/时间。密码、密钥、电话等不发送模型。完整统计与样本分开，精确编号在全量授权集合搜索。

E3：首页、智能体广场、会话/历史搜索、10条分页、重命名、归档恢复、结构化条件、引用抽屉和业务办理入口真实实现。Enter发送/Shift+Enter换行，中文输入法防误发，接口失败保留输入，停止终止后端请求。主体/能力/对象变更开启新会话。本机输入按账号/会话保存；覆盖层保留原推演未保存数据并隐藏背景交互。1280/1680布局经过浏览器检查。

E4：DeepSeek通过服务端现有配置接入，不在前端暴露密钥。服务端校验JSON字段/类型、吨数/时间/位置，模型不能提供坐标或业务命令；当前六智能体负责条件整理及依据解释。需求条件可进入正式需求抽屉显式保存；推演条件通过已校验会话ID带入原推演工作区，坐标待地图确认、指标交由原求解器计算。已有推演调整复用白名单解析服务，显示变化后带回新待算条件，保留原场景。派单、改派、补能确认和事件关闭仍在正式业务工作区执行。

E5：Node全量325项通过（含首批智能体新增10项、原171条AC），隔离浏览器13组通过；真实DeepSeek一次调用、真实SQLite轮次保存和授权来源关联通过。本地主库更新后另做逐页与司机入口只读检查。证据见acceptance-report.md。

接口：GET /api/agents/context、options、conversations、conversations/:id、:id/handoff；POST /api/agents/conversations、:id/messages、:id/cancel、:id/rename、:id/archive。模型请求幂等，账号内防并发，取消与完成竞态保留已完成轮次。模型错误不会写成功轮次。历史引用版本变化标记失效并阻止直接交接，要求重新分析。

限制：业务资料仍为明确标识的仿真资料，模型建议不等于实时现场判断。当前不通过自然语言直接修改正式业务；复杂资源冲突、装卸排队、SOC与费用仍交给对应工作区和计算服务核验。没有已保存计算结果时不会生成虚构推荐指标。没有新增部署流程。

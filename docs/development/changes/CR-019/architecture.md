# CR-019 技术与实施映射

基线：design-baseline-CR-019.json，继承 CR-018，用户批准原文“按这个来帮我开发”。E0 检查、开发授权登记及本地库备份已完成。当前为本地开发，无部署。

## E1 模块拆分

SAF-01 运行监控：完整主体范围查询，车辆/场站/任务/订单/补能/异常关联，采样时效、风险与分页。
SAF-02 异常处置：列表、详情、结构化动作、去重、追加历史、司机要求及确认。
SAF-03 业务交接：订单/任务/计划入口，任务详情定位、场站筛选、异常来源推演核对。
SAF-04 司机端：本人当前关联、公开进展、当前要求确认及补充反馈。
SAF-05 浏览器与接口验证：隔离库完整闭环、冲突、幂等、授权、响应中断恢复、响应式及原运输/能源回归。

## E2 数据库与接口

不修改表结构，alerts 原外键和旧状态保留；data 增加 task_ids/plan_ids/station_id/device_id、incident_type、dedup_key、assignee_id/assignee、due_at、measures、instruction/instruction_revision、driver_receipts、driver_feedback、result、verification、previous_results、history。处理动作追加历史而非替换原始报告。SQL 查询参数化；关联对象同主体检查。同主体/类型/对象未关闭事件按事务去重，重复命令沿 command_results 回放。

GET /api/safety/monitoring：管理员 read；完整计数、分页，10条默认。车辆采样按时间比较来源，10分钟新鲜度参考；过期标最后有效，不写入故障。计划时点超限只提示待核实。不制造低SOC安全阈值，不自动登记告警。场站设备状态及采样来源区分。
GET /api/safety/options：同范围业务引用及有异常处置权限的有效管理员最少标识/姓名/适用主体，不返回账号敏感字段。
GET /api/safety/incidents 和 /:id：查询、状态计数、关联明细。司机先按当前关联过滤，再做检索与分页，不能利用其他任务条件探测关联；脱敏内部处理依据、核验材料、财务字段、他人反馈和无关任务/计划。
GET /api/safety/trace/:vehicle：管理员、明确起止，最大7天、2000条提示截断，历史采样与真实节点事件分开。

incident.report/link/accept/transfer/update/resolve/return/close/reopen/driver-ack/driver-feedback 走既有统一 COMMAND 事务、CSRF、版本、幂等、审计。新工作区事件拒绝用旧 alert.* 命令绕过严格核验，历史旧事件仍可兼容读取和既有命令。待核验显示对应旧待关闭。关闭需有效恢复结论和核验责任确认，不修改任务/订单/补能/工位事实。

场站异常先列同站未结束计划为“待核实关联”，管理员确认关联后才列为受影响任务/订单；不把候选关联直接宣布为交付延误。

## E3 前端

safety-workbench.jsx / safety-panels.jsx / safety-workbench.css 对应两张批准图片。使用现有 React/LobeHub/antd 及颜色变量；没有额外页面大标题。地图、对象与详情、右抽屉同范围联动，字段展示来自 API。表单复用 EnergyForm：字段错误、未保存保护、409读取最新时保留输入、网络结果不明先查询原请求标识。不使用图片中的硬编码业务数据。

手机列表优先，地图按需展开，表格滚动受容器约束。历史记录和已关闭事件可查，不伪造处理明细。司机可见结果单独填写，默认只显示通用恢复结论，内部措施/结果凭证不自动下发。

## E4 业务与地图

复用高德 JSAPI2.0/原服务端安全代理及真实道路路由。新地图独立生命周期清理，当前页对象/选中任务路线/关联站点可定位；虚线明确计划路线，回放只连相邻不超过10分钟的采样点，不用实际道路规划冒充车辆实驶。SDK/路由失败保留列表/轨迹表。临时或历史数据持续标仿真，不改成实时。

任务及订单按原正式工作区操作；重新推演带订单与异常上下文，核对来源可组织余量、已执行量和已派发安排。原任务仍占用运量，须在任务中确认释放/调整后才能组织相应余量；不扩张为自动取消在途任务。司机收到确认只记录阅读要求的版本；管理员更新要求使旧确认不再表示已收到。未接入真实推送、车辆定位上报、设备控制或外部救援服务。

## E5 验证要求

Node用例和原171AC、运行保障浏览器完整闭环、任务及能源浏览器回归、真实本地只读地图响应与页面截图、390至1680像素。所有变更写入测试只用内存SQLite；本地库业务表和records与 pre-cr019 备份逐行对比。原推演用例有运行时刻依赖：将其隔离测试开始时间固定为业务日08:00、截止20:00，继续原司机06:00–22:00排班校验，正式排班规则未放宽。最终结果见 acceptance-report.md，不冒充用户逐节点签署。

# E1 技术方案

采用Node.js24原生SQLite（node:sqlite）、Express5 REST服务和React19＋antd6＋LobeHub前端，esbuild本地构建。开发服务同时提供页面与/api，减少跨源会话复杂性；不增加部署架构。以冻结原型为交互依据，具体页面参考辽粮Transport/Billing/Tracking/Admin/Planning/Driver。

分层为HTTP路由/输入与会话→领域服务→参数化SQLite仓储。transport承担需求/订单/派单与履约；completion补充订单调整、类型化资源、资产事项、阶段比选与反馈；scheduling、charging-model、energy-model分别实现节点运输、补能资源时序与能源策略边界；reporting统一经营统计；assistant提供只读上下文和需核对的输入卡；auditing按实际业务对象归属记录审计。SQLite启用FK/WAL/busy_timeout，金额整数分、数量整数kg、业务时间ISO＋Asia/Shanghai展示。审计和命令幂等结果同事务提交，乐观锁阻止覆盖。

用户登录使用scrypt密码散列和HttpOnly/SameSite会话，写请求校验CSRF，角色、业务范围和操作授权由服务端逐请求核验。种子演示账号仅本地仿真环境使用；司机只能访问本人任务和必要资源，不能用前端角色切换获取管理员数据。

每实体有来源属性、来源引用与版本。seed幂等，不清空已有用户数据库；公开资料和仿真业务事实分离。数据库用确定性业务种子生成近30日订单/车次/补能/费用，统计从有效SQL记录计算；前端无业务数组或整库回写接口。

计划算法为可追溯条件测算：车型容量、当前SOC情景、单趟里程、运输量、适配与站点可用窗口→运输/补能时序及成本等待候选。模拟路网、模型和价格不当成真实道路许可与合同；所有确认仍由业务动作完成，不由AI执行。

高德经服务端配置和安全代理（密钥不进入前端源码）；地图是业务数据叠加，默认示意图可用且标属性。DeepSeek经服务端限时调用、限定授权上下文、只读建议，未配/失败时返回明确错误，不伪造在线模型回答。

验收通过node:test测试真实临时SQLite和HTTP，171条AC逐项通过，Node252个测试计数包含57个父测试；Playwright使用真实服务和会话检查26目的地及流程，两组共47项。100车/10站/1000订单开发基准通过。E0—E5按用户明确后续审批委托记录推荐方案确认；现场启用和投产验收独立，未部署发布。
